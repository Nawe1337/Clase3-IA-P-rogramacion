⚛️ Día 3 · Tu primera app con React + Agentes

Desafío, guía de trabajo y diapositivas — todo en un solo lugar

Duración: ~35 minutos · Herramientas: OpenCode Desktop + Node.js + navegador

Tecnología: React con Vite (proyecto real, con npm)

⚠️ Requisito previo: Node.js instalado (lo hicimos todos juntos en clase). Verificá con node -v en la terminal.

🎯 Objetivo

Construir tu primera aplicación React con Vite: una tarjeta de presentación personal interactiva, trabajando con el agente siguiendo el ciclo de trabajo correcto (pestaña 🛡️ Guía de trabajo).

✅ Requisitos mínimos

  1. 👨‍💼 Avatar (imagen o emoji grande tipo 🧑‍💻) + nombre + rol (ej: "Estudiante de programación")
  2. 📝 Una bio corta (2-3 líneas sobre vos)
  3. 🎯 Una lista de intereses/hobbies (mínimo 4)
  4. 👍 Un botón "Seguir" que al hacer clic cambie a "Siguiendo ✓" (uso de estado)
  5. ❤️ Un contador de likes con botón que sume de a uno (uso de estado)

⚡ Extensiones (si terminás antes — UNA por vez)

NivelExtensión
🌙 1Botón modo oscuro/claro que cambie los colores de la tarjeta
📁 2Sección "Mis proyectos": tarjetas con título + descripción
📝 3Formulario (nombre + mensaje) que muestre un saludo personalizado
🚀 4Caja de búsqueda que filtre tus intereses mientras escribís

🧭 Paso a paso (¡pasos chicos!)

Paso 0 — Preparar el terreno

Creá una carpeta nueva para el proyecto y abrila en OpenCode.

Paso 1 — Pedir el plan (NO el código)

Quiero crear una tarjeta de presentación personal con React + Vite.
Proponeme un plan breve antes de ejecutar cualquier comando.

Chequeá el plan: ¿incluye crear el proyecto con Vite y los 5 requisitos? Si falta algo:

Al plan agregale: un botón de "Seguir" y un contador de likes.

Paso 2 — Crear el proyecto

Me gusta el plan. Creá el proyecto con Vite (template react) en la
carpeta "mi-tarjeta", ejecutá la instalación de dependencias y
explicame qué hizo cada comando.

Al terminar: revisá cada permiso que pide (¿qué comando va a correr?), aceptá, y verificá que puedas abrir http://localhost:5173 en el navegador.

Paso 3 — Limpiar y poner la estructura base

Limpiá el contenido de ejemplo de App.jsx y dejá solo un componente
Tarjeta con avatar (emoji), mi nombre, rol y bio.
Mis datos: [TU NOMBRE], [TU ROL], [TU BIO].

Al terminar: mirá el navegador — la web se recarga sola al guardar ✨

Paso 4 — Lista de intereses

Ahora agregá dentro de la tarjeta una sección "Mis intereses"
con esta lista: [INTERÉS 1], [INTERÉS 2], [INTERÉS 3], [INTERÉS 4].

Paso 5 — Botón Seguir (¡estado!)

Agregá un botón que diga "Seguir". Al hacer clic debe cambiar
a "Siguiendo ✓" y volver a "Seguir" si clickeo de nuevo.
Usá estado de React. Explicame brevemente cómo funciona.

Paso 6 — Contador de likes

Agregá un botón de corazón con un contador que empiece en 0
y sume 1 en cada clic.

Paso 7 — Estilo

Mejorá el diseño: tarjeta centrada, bordes redondeados, sombra suave,
buena tipografía. Paleta: [TUS COLORES o "elegila vos con buen gusto"].

Paso 8 — Si algo se rompe

Al hacer clic en [X] no pasa nada. La consola del navegador (F12)
muestra este error: [PEGA EL ERROR EXACTO].
¿Qué significa y cómo lo arreglo?

🔧 ¿Se cortó el servidor de desarrollo? Pará la terminal y volvé a ejecutar npm run dev, o pedile al agente que lo levante.

Paso 9 — Extensiones

Elegí UNA de la tabla y escribí tu propio prompt. 💪

📋 Criterios de éxito

  • Los 5 requisitos funcionan en http://localhost:5173
  • Leíste (y entendiste mayormente) cada diff que aceptaste
  • Probaste después de cada paso
  • Bonus: le pediste al agente que te explique una parte del código
🎯 Recuerdo del día: el agente acelera tus manos, no reemplaza tu cabeza.

1. La mentalidad: tú eres el supervisor

Un agente de IA (como el que corre dentro de OpenCode) no es un robot todopoderoso ni un simple autocompletado. Es un asistente muy rápido pero poco confiable:

  • ✅ Es excelente para: escribir código repetitivo, explicar, refactorizar, encontrar errores.
  • ⚠️ Es débil para: saber exactamente qué TÚ quieres, verificar que funciona, cuidar tus datos.
Regla base: el agente propone, tú dispones. Nada entra a tu código sin que lo leas.

2. Antes de escribir cualquier prompt

  1. Entendé la tarea: ¿qué quiero construir? ¿cómo se ve funcionando?
  2. Dividí en pasos chicos: si tu idea necesita más de una frase para describirla, son varios prompts.
  3. Tené un plan: pedile primero el plan al agente, no el código.
❌ "Haceme una página con todo"
✅ "Quiero X. Proponeme un plan breve antes de escribir código."

3. Anatomía de un buen prompt

ParteQué llevaEjemplo
📋 ContextoQué proyecto, qué existe ya"Tengo un proyecto React con Vite"
🎯 ObjetivoUna sola cosa concreta"Agregá un botón que cuente clics"
🚧 RestriccionesLímites y estilo"Sin librerías externas, tema oscuro"
📐 FormatoQué querés de vuelta"Primero el plan, después el código"
  • Sé específico: números, colores, textos exactos. "Un botón azul (#58a6ff) con texto grande".
  • Da ejemplos: "algo como el perfil de GitHub, en chico".
  • Pedí explicaciones: "explicame qué hiciste" es tu mejor herramienta de aprendizaje.
  • Una cosa por prompt: si pedís 5 cosas, cuando falle no sabrás cuál rompió.

4. El ciclo de trabajo (memorizalo)

🤔 PENSAR → 📋 PEDIR PLAN → ✍️ PROMPT CHICO → 🔍 REVISAR EL DIFF → 🌐 PROBAR → ↺ REPETIR

Si algo se rompe

  1. No escribas "no anda".
  2. Abrí la consola del navegador: F12 → pestaña Console.
  3. Copiá el mensaje de error exacto (texto rojo).
  4. Pegaselo al agente: "Al hacer clic en el botón no pasa nada. La consola muestra Uncaught ReferenceError: useState is not defined. ¿Qué significa y cómo lo arreglo?"

5. Reglas de prudencia (¡no negociables!)

Con el agente

  • Leo siempre el diff antes de aceptar un cambio.
  • No acepto comandos que no entiendo: primero pregunto "¿qué hace esto?".
  • Pido explicaciones de código que no comprendo.
  • Verifico en el navegador después de cada cambio, no "confío".
  • Uso pasos chicos: una feature por prompt.

Seguridad

  • Nunca pego contraseñas ni API keys en el chat.
  • No pongo datos personales privados en archivos que le paso al agente.
  • Solo doy permisos de escritura dentro de mi proyecto.
  • Desconfío de librerías desconocidas que el agente quiera instalar.

Respaldo

  • Guardo una copia de mi carpeta antes de cambios grandes.
  • Cuando aprendamos git: commits frecuentes con mensajes claros.

6. Vocabulario rápido

TérminoSignificado

HarnessEl entorno que conecta modelo + herramientas + tus archivos (OpenCode).
SesiónUna conversación con el agente, con memoria de tu proyecto.
DiffVista de qué líneas de código se agregan/quitan en un cambio.
PromptLa instrucción que le das al agente.
MCP (Model Context Protocol)Protocolo estándar para conectar agentes con herramientas externas (GitHub, navegador, bases de datos).
SkillPaquete de instrucciones reutilizables para tareas repetibles (la "receta de la casa").
AlucinaciónCuando el agente inventa con seguridad algo falso (una librería, una función).
