04¿Qué es un agente de código?

💬 Chat normal

Te da código… y tú lo copias, lo pegas, lo guardas y lo probás.

🤖 Agente

Piensa → actúa → observa → repite. Lee y edita tus archivos, ejecuta comandos y verifica el resultado. Tú eres el supervisor.

🧠 Piensa
(el modelo planea)
↓
🔧 Usa herramientas
(lee / edita / ejecuta)
↓
👀 Observa el resultado
↓ ↺ repite hasta lograr la tarea

05OpenCode: nuestro "cockpit"

OpenCode es el harness: el entorno que conecta al modelo con tus archivos y herramientas.

💬 Sesión

Conversación con memoria de tu proyecto. Lo que ya dijiste no hace falta repetirlo… pero conviene ser claro igual.

🔒 Permisos

El agente pide permiso antes de editar o ejecutar. Es tu momento de decidir: ¡leé siempre qué pide!

🔍 Diff (cambios)

Te muestra exactamente qué líneas van a cambiar. Rojo = se quita, verde = se agrega.

📐 Regla de oro

Nada entra a tu código sin que tú lo veas. Aceptar sin leer es la mala costumbre #1.

06El prompt es la nueva interfaz

Antes programabas escribiendo código.

La calidad de la salida depende de la calidad de la entrada.

07Anatomía de un buen prompt

1 · Contexto 📋

¿Qué proyecto es? ¿Qué existe ya? "Tengo un proyecto React con Vite…"

2 · Objetivo concreto 🎯

Una sola cosa clara y verificable. "Agregá un botón que cuente clics."

3 · Restricciones 🚧

Colores, estilo, límites. "Sin librerías externas. Tema oscuro."

4 · Formato / plan 📐

"Primero proponerme un plan breve, después el código."

💡 Truco pro: pedí el plan antes que el código. Corregir un plan cuesta 10 segundos; corregir 200 líneas, mucho más.

08Prompts: malos vs buenos

❌ Malos

  • "Haceme una página"
  • "Está mal, arreglalo"
  • "Haceme el sitio entero de una vez"
  • "No anda" (y nada más)

✅ Buenos

  • "Tengo un proyecto React con Vite. Agregá en App.jsx un botón que cuente clics y muestre el número al lado. Sin librerías extra."
  • "El botón no incrementa. La consola muestra useState is not defined. Revisá y explicame el error."

🔎 Notá el patrón: contexto + objetivo + detalle del error exacto.

09Iterá en pasos chicos

_PEDIR UNA cosa chica_
↓
_REVISAR el diff_
↓
_PROBAR en el navegador_
↓
_SIGUIENTE cosa_ ↺

¿Por qué?

  • Los errores son fáciles de detectar (cambió una cosa)
  • Aprendés de cada cambio en vez de recibir una bola de código
  • Controlás el rumbo: el agente no se va por las ramas

NO: "haceme todo el sitio de una".

10¿Qué es MCP?

Model Context Protocol — un protocolo abierto y estandarizado para conectar modelos de IA con herramientas y servicios externos.

🔌 Analogía: el enchufe universal

Antes, cada app de IA inventaba su propio "enchufe" para conectarse a GitHub, bases de datos, etc. MCP define un solo enchufe estándar: cualquier agente se conecta a cualquier servidor MCP (GitHub, navegador, base de datos…).

Agente (OpenCode) 🔌 ←MCP→ 🔌 GitHub · 🔌 Navegador · 🔌 Base de datos

11MCP en la práctica

🐙 Servidor GitHub

El agente puede crear issues, revisar pull requests, buscar código en repos.

🌐 Servidor Navegador

El agente abre tu página, hace clic, toma capturas y te dice si se ve bien.

🗄️ Servidor Base de datos

El agente consulta y modifica datos reales (con tus permisos).

⚙️ En OpenCode

Los servidores MCP se configuran una vez y aparecen como herramientas nuevas para el agente. Se listan y administran desde la app.

Hoy no los necesitamos — pero es la pieza que hace que un agente escale más allá de editar archivos.

12¿Qué son las Skills?

Una skill es un paquete de instrucciones y recursos para tareas repetibles: "la receta de la casa".

📦 Qué contiene

Instrucciones paso a paso (en Markdown), plantillas, scripts. El agente la carga cuando tu tarea coincide con ella.

🧁 Ejemplos

"Cómo hacer deploy a producción", "Cómo escribir tests", "Cómo estructurar un proyecto React". Le enseñás una vez, lo usa siempre.

💡 Así personalizás al agente sin reprogramarlo: le das instrucciones escritas, no código.

14Trabajar con prudencia: reglas de oro 🛡️

  1. Pensá antes de pedir. ¿Qué querés exactamente? ¿Cómo se ve terminado?
  2. Pedí pasos chicos. Una feature por prompt.
  3. Leé siempre el diff antes de aceptar un cambio.
  4. Probá en el navegador después de cada cambio.
  5. Guardá tu avance. Copia de seguridad o git.
  6. Pedí explicaciones. "¿Qué hiciste y por qué?" es un prompt poderoso.

15El agente no es infalible ⚠️

Errores típicos

  • Inventa funciones o librerías que no existen (alucinaciones)
  • Rutas de archivo incorrectas
  • Código que "parece" correcto pero no funciona
  • Sobreconfianza: nunca dice "no sé"

Tu rol: control de calidad

  • Si no entendés un cambio, no lo aceptes: pedí que lo explique
  • Verificá en el navegador, no confíes en "ya está listo"
  • Desconfiá de respuestas larguísimas a preguntas simples

16Seguridad básica 🔐

  • Nunca pegues contraseñas ni API keys en el chat
  • No aceptes comandos que no entendés — antes preguntá: "¿qué hace esto?"
  • No le des permisos de escritura fuera de tu proyecto
  • Cuidado con "instalá esta librería": verificá que sea conocida
  • Tu código puede ir a servidores externos: no pongas datos privados en archivos que le pasás al agente

17¿Qué es React? ⚛️

Biblioteca de JavaScript para construir interfaces (creada por Meta, 2013). Tres ideas clave:

🧱 Componentes

Piezas reutilizables e independientes: un botón, una tarjeta, un menú. Como bloques de Lego.

📥 Props

Los datos que entran a un componente desde afuera. Configuran cómo se ve.

⚡ Estado (state)

Los datos que cambian. Cuando cambian, React re-dibuja la pantalla solo. ¡Magia!

🎯 Hoy

Con estos 3 conceptos + un agente, vas a construir tu primera app interactiva.

18JSX en 60 segundos

JSX = HTML dentro de JavaScript. Así se escribe un componente React:

function Tarjeta() {
  const nombre = "Ana";
  return (
    <div className="tarjeta">   {/* ojo: className, no class */}
      <h1>Hola, {nombre}</h1>   {/* {} para meter JS */}
      <p>Mi primera app React</p>
    </div>
  );
}
  • {"{ }"} → para insertar JavaScript dentro del HTML
  • className en vez de class
  • Todas las etiquetas se cierran: <img />

19Instalamos Node.js ⚙️

Node.js ejecuta JavaScript fuera del navegador. Es la puerta al mundo profesional: npm (el "app store" de paquetes), Vite, y miles de librerías.

Opción A — Instalador (recomendada)

1. Entrar a nodejs.org
2. Descargar la versión LTS (botón verde)
3. Siguiente → Siguiente → Instalar ✅

Opción B — Terminal (Windows)

winget install OpenJS.NodeJS.LTS

Lo puede hacer el agente por vos… ¡pero ahora entienden qué hace!

✅ Verificación: abrir una terminal nueva y escribir node -v y npm -v → deben mostrar números de versión.

20Nuestro proyecto con Vite ⚡

Vite es la herramienta estándar para crear proyectos React: servidor de desarrollo con recarga instantánea, archivos organizados, listo para crecer.

npm create vite@latest mi-tarjeta -- --template react
# el agente puede ejecutar esto por nosotros…
cd mi-tarjeta
npm install
npm run dev   # → http://localhost:5173 🎉

📁 Estructura clave

src/App.jsx → tu componente principal
src/index.css → estilos
Guardás → el navegador se actualiza solo.

🤖 Hoy el agente hace esto

Vos pedís, el agente crea el proyecto, instala y levanta el servidor. Pero vos entendés qué está pasando — esa es la diferencia.

21Demo en vivo: el primer prompt 🎬

1 · Pedimos el plan primero:

Quiero crear una tarjeta de presentación personal con React + Vite.
Proponeme un plan breve antes de ejecutar cualquier comando.

2 · Aprobamos y dejamos que arme la base:

Me gusta el plan. Creá el proyecto con Vite (template react) en la
carpeta mi-tarjeta, instalá las dependencias y levantá el servidor
de desarrollo. Después limpiá App.jsx y dejá solo un componente
Tarjeta con nombre, rol y una frase.

👀 Miren cómo OpenCode pide permiso para cada comando, muestra el diff, y la web se recarga sola al guardar.
