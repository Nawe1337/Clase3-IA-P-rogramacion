03SDD — Spec-Driven Development 📝

Antes de pedirle código al agente, escribimos QUÉ queremos y CÓMO sabemos que está bien.

📝 Spec
→
✅ Criterios
→
🧪 Tests
→
💻 Código
  • Requisitos numerados: R1, R2…
  • Criterios: Dado / Cuando / Entonces
  • Fuera de alcance: lo que HOY no hacemos
# docs/SPEC.md (tienda-prueba)

### R2 · Buscador
- CA-2.1 Cuando escribo un texto, solo veo
  productos cuyo nombre o marca lo contienen.
- CA-2.2 Ignora mayúsculas y acentos
  ("rafaga" encuentra "Ráfaga").
- CA-2.3 Con el texto vacío, veo todos.

## 🚫 Fuera de alcance (Fase 1)
- Backend, API, base de datos → Fase 2

04TDD — primero el test 🔴🟢🔵

🔴 ROJO

Escribís el test antes del código. Lo corrés: falla (todavía no existe nada). ¡Bien!

🟢 VERDE

Escribís lo mínimo para que el test pase. Ni una línea más.

🔵 REFACTOR

Ordenás y mejorás el código. Los tests te avisan si rompiste algo.

// src/logic/filtros.test.js  ← CA-2.2
it('ignora mayúsculas y acentos', () => {
  const r = filtrarProductos(lista, { texto: 'RAFAGA' })
  expect(ids(r)).toEqual([1])
})

Corre con Vitest (el de Vite):

npm run test:run

tienda-prueba: 30 tests en verde ✅ — cada CA de la spec tiene su test.

08🚧 ¿Qué NO puede hacer una tienda solo-front?

Problema¿Por qué?¿Quién lo resuelve?
Cambiar un precio o agregar una zapatillaHay que editar el código y volver a publicar🗄️ Base de datos
Que el precio sea confiableTodo lo del navegador se puede tocar (F12 😈)⚙️ Backend

09⚙️ Backend + 🗄️ base de datos — el mapa

🖥️ Navegador
React · :5173
⇄
HTTP + JSON
⚙️ API
Node + Express · :3001
⇄
SQL
🗄️ Base de datos
SQLite (un archivo)

🖥️ Frontend

Lo que se ve. Pide datos y los muestra. No guarda nada importante.

⚙️ Backend

El mostrador: recibe pedidos, valida, calcula el precio real, habla con la BD.

🗄️ Base de datos

El depósito: tablas con filas, que quedan guardadas aunque se apague todo.

🍔 Analogía: vos (front) pedís en el mostrador (API), la cocina busca en la heladera (BD). Nunca entrás a la cocina.

  • GET = "dame" · POST = "guardá esto" · la respuesta siempre es JSON (como nuestros objetos de JS)

SELECT * FROM productos

SQLite: la BD es un solo archivo (pisada.db). Sin instalar servidores: ideal para aprender.

12🔑 El .env vuelve… ahora en los dos lados

🖥️ Front · tienda-prueba/.env

VITE_PORT=5173
VITE_NOMBRE_TIENDA=Pisada
VITE_API_URL=http://localhost:3001/api

Todo lo VITE_ es público: solo direcciones y textos.

⚙️ Back · backend/.env

PORT=3001
DB_PATH=./pisada.db
ORIGEN_PERMITIDO=http://localhost:5173
# CLAVE_PAGOS=…  ← los secretos de verdad, ACÁ

Nunca llega al navegador → acá sí van los secretos.

Los dos .env están en el .gitignore y cada proyecto tiene su .env.example para que el compañero sepa qué completar.

13🔁 La mudanza — cambia UN archivo

Antes · Fase 1

export async function obtenerProductos() {
  return structuredClone(productos)
}

Después · Fase 2

const API = import.meta.env.VITE_API_URL

export async function obtenerProductos() {
  const res = await fetch(`${API}/productos`)
  if (!res.ok) throw new Error('No cargó')
  return res.json()
}
  • Componentes, filtros y carrito: no se tocan ✅
  • Corremos npm run test:run → si queda en verde, la mudanza salió bien 🟢
