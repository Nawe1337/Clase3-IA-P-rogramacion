03Git ≠ GitHub

🌿 Git — el programa

  • Se instala en tu compu
  • Guarda el historial: cada cambio es un "punto de guardado"
  • Funciona sin internet
  • 🎮 Como los checkpoints de un videojuego

🐙 GitHub — la nube

  • Una página web: github.com
  • Aloja tus repos: los tenés en cualquier compu
  • Para compartir, colaborar y publicar páginas
  • ☁️ Como el Google Drive de los programadores

Git guarda en tu compu → y sube a GitHub. Tu perfil de GitHub = tu portfolio 💼

06⚙️ Instalar Git + decirle quién sos

Windows (clic para copiar):

winget install --id Git.Git -e --source winget

Mac:

xcode-select --install

Cerrá y abrí la terminal y verificá:

git --version

Una sola vez por compu, con TUS datos:

git config --global user.name "Tu Nombre"
git config --global user.email "tu-mail@ejemplo.com"
git config --global init.defaultBranch main

💡 Usá el mismo mail de GitHub: así tus commits aparecen en tu perfil (los cuadraditos verdes 🟩).

07🛡️ ANTES de subir: el .gitignore

⚠️ La trampa

El .gitignore que crea Vite excluye node_modules… pero NO excluye el .env.

Repo público + .env subido = tu secreto en internet. Hay bots que escanean GitHub buscando claves todo el día 🤖

✅ Revisá que tenga esto

node_modules
dist
.env
.env.local

Y subí un .env.example: los nombres de las variables, sin valores secretos.

Lo que vimos en el Día 4 (.env) cobra sentido hoy 🔑

08📦 Crear el repo vacío en GitHub

  1. Botón + (arriba a la derecha) → New repository
  2. Nombre: mi-tienda (sin espacios ni acentos)
  3. Public (portfolio) o Private (solo vos)
  4. NO marques README, .gitignore ni licencia → el repo nace vacío
  5. Create repository → copiá la URL que termina en .git
# la URL se ve así:
https://github.com/TU-USUARIO/mi-tienda.git

💡 ¿Por qué vacío? Si GitHub crea un README y tu compu tiene otros archivos, los dos "historiales" no coinciden y el push se rechaza.

09🚀 Práctica 2 — tu primer push

1) En la terminal, dentro de mi-tienda:

git init
git add .
git status

👀 Mirá la lista: si aparece .env o node_modules → pará y revisá el .gitignore.

2) Commit + conexión + subida (tu URL):

git commit -m "Primera versión de mi-tienda"
git branch -M main
git remote add origin https://github.com/TU-USUARIO/mi-tienda.git
git push -u origin main

🌐 La primera vez se abre el navegador para iniciar sesión → autorizás → listo. Recargá tu repo: ¡ahí está! 🎉

11🤖 Git con el agente

Primera vez (con el repo vacío ya creado):

Quiero subir este proyecto a GitHub, a este repo vacío:
https://github.com/TU-USUARIO/mi-tienda.git
Hacelo paso a paso, explicándome cada comando:
1) Revisá que el .gitignore excluya node_modules,
   dist y .env (agregá lo que falte).
2) Creá un .env.example sin valores secretos.
3) git init + git add y mostrame el git status.
   Esperá mi OK antes del commit.
4) Con mi OK: commit, remote y push.

Día a día:

Hacé un commit con lo que cambiamos recién:
mostrame el git status, proponé un mensaje
claro en español y esperá mi OK antes del push.

⚠️ Igual que siempre

Leé el git status antes de aceptar. El agente también se puede equivocar y subir el .env.

12💻 → 🏠 Seguir en otra compu

En la compu nueva (con Git + Node):

git clone https://github.com/TU-USUARIO/mi-tienda.git
cd mi-tienda
npm install

Después: copiá .env.example → .env y npm run dev.

  • ¿Por qué npm install? Porque node_modules no viaja (pesa cientos de MB y se regenera con el package.json)
  • ¿Por qué crear el .env? Porque nunca viaja: ¡esa es la idea!
  • Antes de trabajar en una compu donde ya tenías el repo: git pull ⬇️

13🌐 Bonus: GitHub Pages — hosting gratis

  1. Repo con un index.html en la raíz (ej: tu página del Día 2)
  2. Settings → Pages
  3. Source: Deploy from a branch · main · / (root) → Save
  4. 1-2 minutos → TU-USUARIO.github.io/REPO/ 🎉

👀 Ya lo usaron sin saberlo

La guía del curso (la del QR) está publicada exactamente así: un repo en GitHub + Pages.

⚛️ mi-tienda (React) primero hay que compilarla con npm run build: eso va en la clase de deploy.
